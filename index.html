Cost Control & Variance

The module the company lacks today: every project's committed cost vs forecast vs budget, with automatic over-budget flags so overspend is caught in days, not at year-end.

Early-Warning Alerts

The engine running underneath every view. Rules fire automatically on cost, schedule and procurement signals — pushed to email / Teams so issues reach a manager the same week, not the next quarterly review.

0 active alerts
Each alert is a configurable rule: cost (variance > threshold, commitment > budget), schedule (baseline slip > N days, 0% complete past start), procurement (PO past sealift cut-off, long-lead item not ordered). Thresholds are owned by Finance & the PMO, not hard-coded.

Recommended tech stack

Chosen for low cost, low IT overhead and Arctic-friendly bandwidth — right-sized for an SME.
Frontend: React + Chart.js
Backend: Python (FastAPI)
Database: PostgreSQL
Pipeline: Airbyte / dbt
Hosting: Azure (Canada region)
Auth: Microsoft Entra ID (SSO)
Alerts: Teams + SMTP
BI export: Power BI compatible
Alternative no-code path for fastest start: Power BI + Power Automate + SharePoint lists. Same logic, lower build cost, slightly less flexible — a good Phase-0.

Core data model

Five tables are enough to power every view in this prototype.
EntityKey fields
Projectid, name, site, sponsor, baseline_budget, status
Commitmentpo_id, project_id, engaged_cost, actual_cost, vendor, lead_time
Forecastproject_id, etc, forecast_at_completion, period
Milestoneproject_id, name, start, end, baseline_finish, pct_complete
AlertRuletype, metric, operator, threshold, owner, channel
Variance = Budget − Forecast. Forecast = committed cost + estimate-to-complete. Recomputed on every commitment, so the dashboard is never more than minutes stale.
